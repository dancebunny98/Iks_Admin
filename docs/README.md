# IksAdmin_CustomMenus

Модуль-конструктор произвольных меню внутри `!admin`. Позволяет полностью через
JSON-конфиг (без правки кода и пересборки плагина) добавлять свои пункты меню,
вложенные подменю любой глубины, пункты-переключатели с динамическим заголовком,
и опциональные чат-команды-алиасы. Каждый пункт/подменю может иметь собственные
права доступа.

Конфиг лежит в `configs/plugins/IksAdmin_CustomMenus/IksAdmin_CustomMenus.json`
(создаётся автоматически с примером при первом запуске плагина).

---

## 1. Как это встраивается в !admin

Каждая запись в `Menus` (см. схему ниже) добавляет **один пункт в главное меню
`!admin`**, рядом со встроенными «Управление серверами» / «Управление игроками» и
т.д. Клик по этому пункту открывает список `Items` этого меню.

Если `Items` содержит пункт с `Submenu` — клик по нему открывает ещё один уровень
меню, и так далее: **вложенность не ограничена**. Кнопка «Назад» на каждом уровне
всегда корректно ведёт на уровень выше (вплоть до самого `!admin`).

---

## 2. Полная схема конфига

```jsonc
{
  "AnnounceToAll": true,      // объявлять ли всем в чат о выполнении пункта меню
  "Menus": [
    {
      "Id": "match_control",       // уникальный id меню (только латиница/цифры/_, без пробелов)
      "Title": "Match Management", // заголовок пункта в !admin И заголовок самого меню
      "ViewFlags": "z",            // права по умолчанию для ВСЕХ пунктов этого меню
      "Items": [ /* см. ниже */ ]
    }
  ]
}
```

### Пункт меню (`CustomMenuItem`)

```jsonc
{
  "Id": "pause",                    // уникален в пределах своего родителя (не глобально)
  "Title": "Pause Match",           // заголовок в обычном состоянии
  "ViewFlags": null,                // null/не задано = наследуется от родителя (см. раздел 4)

  // --- вариант А: пункт-команда ---
  "Command": "mp_pause_match",      // консольная команда сервера (без "css_")
  "ToggleTitle": "Resume Match",    // если задано вместе с ToggleCommand - пункт-переключатель
  "ToggleCommand": "mp_unpause_match",
  "FeedbackMessage": null,          // текст в чат после выполнения; null = берётся заголовок
  "Alias": "pausematch",            // опционально: !pausematch тоже сработает (см. раздел 6)

  // --- вариант Б: пункт-подменю (взаимоисключающе с Command/Toggle*/Alias) ---
  "Submenu": null                   // если задано (список таких же пунктов) - открывает вложенное меню
}
```

Пункт — это **либо** команда (`Command`/`Toggle*`/`Alias`), **либо** подменю
(`Submenu`). Если задано `Submenu` — остальные поля действия игнорируются.

---

## 3. Базовое меню (плоский список)

```json
{
  "Id": "quick_actions",
  "Title": "Quick Actions",
  "ViewFlags": "z",
  "Items": [
    { "Id": "end_warmup", "Title": "End Warmup", "Command": "mp_warmup_end" },
    { "Id": "restart_round", "Title": "Restart Round", "Command": "mp_restartgame 1" }
  ]
}
```

В `!admin` появится пункт «Quick Actions» → список из двух команд. Клик — команда
выполняется на сервере, админу и (если `AnnounceToAll: true`) всем в чат приходит
подтверждение, меню тут же переоткрывается на этом же уровне.

---

## 4. Права доступа (ViewFlags) и наследование

Формат — тот же, что используется во всём IksAdmin (как в `viewFlags` у
`AddMenuOption`): `"*"` — видно всем, `"z"` — обычный админский флаг, можно
комбинировать буквы (`"zt"`, `"bcd"` и т.д.), либо `"not override"`, если такая
семантика нужна вашей конфигурации групп.

**Правило наследования:** если у пункта/подменю `ViewFlags` не задано (`null`
или поле отсутствует в JSON) — он наследует права от родителя:

```
CustomMenuDefinition.ViewFlags ("z" по умолчанию)
  → Item.ViewFlags (если null - наследует выше)
    → Submenu.Item.ViewFlags (если null - наследует выше, и так далее)
```

Это значит:
- Ничего не указывая нигде — **всё меню целиком доступно только тем, у кого есть
  флаг `z`** (обычный админский доступ), это дефолт из коробки, как вы и просили.
- Достаточно один раз поменять `ViewFlags` меню верхнего уровня, чтобы права
  применились сразу ко всем пунктам и подменю внутри, если они сами ничего не
  переопределяют.
- Отдельному пункту (или целому подменю) можно дать **более узкие** (или более
  широкие) права, чем у родителя, задав ему свой `ViewFlags` — это не повлияет
  на остальные пункты рядом.

Пример: меню целиком под `"z"`, но конкретное подменю «Team Controls» доступно
только под более редким флагом `"zt"`:

```json
{
  "Id": "match_control",
  "Title": "Match Management",
  "ViewFlags": "z",
  "Items": [
    { "Id": "end_warmup", "Title": "End Warmup", "Command": "mp_warmup_end" },
    {
      "Id": "team_controls",
      "Title": "Team Controls",
      "ViewFlags": "zt",
      "Submenu": [
        { "Id": "swap_teams", "Title": "Swap Teams", "Command": "mp_swapteams" }
      ]
    }
  ]
}
```

Игрок с флагом `z`, но без `t`, увидит в «Match Management» только «End Warmup» —
пункт «Team Controls» будет скрыт для него, но виден админам с `zt`.

Чтобы сделать меню публичным (видно вообще всем на сервере, не только админам) —
поставьте `"ViewFlags": "*"` на нужном уровне.

## 5. Пункты-переключатели (Toggle)

Если у пункта заданы **и** `ToggleTitle`, **и** `ToggleCommand` — он становится
переключателем с двумя состояниями:

| Состояние | Заголовок в меню | Что выполнится по клику | Что станет после клика |
|---|---|---|---|
| обычное | `Title` | `Command` | переключается в "toggled" |
| toggled | `ToggleTitle` | `ToggleCommand` | переключается в "обычное" |

```json
{
  "Id": "pause",
  "Title": "Pause Match",
  "Command": "mp_pause_match",
  "ToggleTitle": "Resume Match",
  "ToggleCommand": "mp_unpause_match"
}
```

Открыли меню → видите «Pause Match» → нажали → выполнилась `mp_pause_match`,
меню тут же переоткрылось, и **этот же пункт** теперь называется «Resume Match».
Нажали ещё раз → выполнилась `mp_unpause_match`, заголовок вернулся в «Pause
Match». Именно тот сценарий, который вы описывали.

Состояние переключателей хранится в памяти плагина, отдельно для каждого
конкретного пункта (по полному пути до него в дереве меню, так что одинаковый
`Id` в разных подменю никогда не перепутается). При перезапуске сервера/плагина
все переключатели сбрасываются в исходное состояние — это осознанно: «матч на
паузе» не должно считаться фактом, пережившим рестарт.

---

## 6. Алиас-команды (опционально, по умолчанию выключено)

По умолчанию пункт меню **не создаёт никакой отдельной команды** — доступен
только через дерево `!admin`, как вы и просили. Если для конкретного пункта
хочется ещё и быстрый чат-ярлык — добавьте `Alias`:

```json
{ "Id": "pause", "Title": "Pause Match", "Command": "mp_pause_match",
  "ToggleTitle": "Resume Match", "ToggleCommand": "mp_unpause_match",
  "Alias": "pausematch" }
```

Это зарегистрирует `!pausematch` / `/pausematch` / `css_pausematch` как
дополнительный способ выполнить ровно то же действие (с учётом текущего
состояния переключателя), в обход меню. Право на алиас — то же эффективное
`ViewFlags`, что и у самого пункта (с учётом наследования из раздела 4).

Пункты без `Alias` (то есть по умолчанию — все) остаются недоступны как команда
вообще, только через `!admin`.

Подменю (`Submenu`) сами по себе `Alias` не поддерживают — он имеет смысл только
у пунктов-команд, но обходит вложенные подменю рекурсивно: если `Alias` задан у
пункта где-то глубоко внутри вложенного подменю, команда всё равно
зарегистрируется корректно.

---

## 7. Листание страниц (пагинация)

Ничего настраивать не нужно — если пунктов в меню больше, чем помещается на
экран, движок меню (`MenuManagerCS2`/WASD-меню, либо чат/консольный fallback,
если `MenuManagerCS2` не установлен) **автоматически** показывает следующую/
предыдущую страницу. Это поведение самого движка меню, общее для всего
`IksAdmin`, а не что-то специфичное для этого модуля — работает одинаково что
для `!admin`, что для любого вложенного меню отсюда.

---

## 8. Как добавить своё меню/пункт

1. Остановите сервер (или используйте `css_plugins reload IksAdmin_CustomMenus`,
   если конфиг перечитывается на reload — иначе перезапустите карту/сервер).
2. Откройте `configs/plugins/IksAdmin_CustomMenus/IksAdmin_CustomMenus.json`.
3. Добавьте новый объект в `Menus` (для нового пункта в `!admin`) или новый
   объект в чей-то `Items`/`Submenu` (для нового пункта внутри существующего
   меню) — по образцу выше.
4. Сохраните файл, перезапустите сервер/плагин.

Пересобирать и переустанавливать сам плагин не нужно — вся структура меню
целиком читается из JSON при загрузке.

## 9. Полный пример (то, что уже лежит в конфиге по умолчанию)

```json
{
  "AnnounceToAll": true,
  "Menus": [
    {
      "Id": "match_control",
      "Title": "Match Management",
      "ViewFlags": "z",
      "Items": [
        {
          "Id": "end_warmup",
          "Title": "End Warmup",
          "Command": "mp_warmup_end"
        },
        {
          "Id": "pause",
          "Title": "Pause Match",
          "Command": "mp_pause_match",
          "ToggleTitle": "Resume Match",
          "ToggleCommand": "mp_unpause_match",
          "Alias": "pausematch"
        },
        {
          "Id": "team_controls",
          "Title": "Team Controls",
          "ViewFlags": "zt",
          "Submenu": [
            { "Id": "freeze_all", "Title": "Freeze All Players", "Command": "mp_freezetime 9999; sm_slay @all 0" },
            { "Id": "swap_teams", "Title": "Swap Teams", "Command": "mp_swapteams" }
          ]
        }
      ]
    }
  ]
}
```

Это даёт в `!admin` пункт **«Match Management»**, внутри которого:
- **End Warmup** — обычная команда, доступна всем с флагом `z`;
- **Pause Match** ⇄ **Resume Match** — переключатель, плюс `!pausematch` в чате;
- **Team Controls** — вложенное подменю (видно только флагу `zt`), внутри —
  ещё два обычных пункта-команды.

---

## 10. На что обратить внимание

- **`Id` должен быть уникален только среди «соседей»** (в пределах одного
  `Items`/`Submenu`) — не глобально по всему конфигу. Между РАЗНЫМИ подменю
  одинаковые `Id` использовать можно.
- **`Command` выполняется буквально** через серверную консоль
  (`Server.ExecuteCommand`) — это не команда чата (`css_...`), а именно
  ConVar/консольная команда сервера. Если нужно выполнить несколько команд
  подряд — большинство ConVar-команд в Source-движке поддерживают разделение
  через `;` в одной строке (как в примере с `freeze_all` выше), но перед боевым
  использованием стоит проверить на тестовом сервере.
- **`Alias` — по желанию, не обязателен.** Если не указывать вообще нигде в
  конфиге — ни один пункт не получит отдельной команды, ровно как вы и просили
  по умолчанию.
- Права проверяются **и** при построении меню (скрытые пункты не отображаются
  вовсе), **и** при выполнении алиас-команды в чате — так что скрытый в меню
  пункт с алиасом не получится вызвать командой в обход прав.
